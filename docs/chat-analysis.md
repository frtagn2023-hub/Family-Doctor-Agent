# Hermes 聊天观察：分析与接入

聊天观察由正在与用户交流的 Hermes 模型完成。模型查看本轮原始多轮上下文，逐项分析九个维度，用精确原句支持结构化观察；本地工具校验后只保存枚举、计数和哈希。没有新增外部模型服务，不读取其他人的历史会话，不在 Web 展示对话原文或分析长文。

认知变化提示只出现在本机 Web。不会主动通过飞书通知老人或发送风险分析报告；正常健康交流和真实急症的当轮安全协助继续有效。用户询问观察功能时如实解释，不能将这一设置理解为隐瞒或欺骗。

## 两种执行方式

**推荐：可选 Hermes 插件。** 启用后，`pre_llm_call` 在进程内保存本轮原始用户文本并注入执行流程；`post_llm_call` 将成功完成的助手回复作为下一轮的上下文。模型通过 `family_cognition_prepare` 获取当前窗口与模板，分析后调用 `family_cognition_record`。详细安装、配置与合成验证见[插件说明](../integrations/hermes/family-doctor-cognition/README.md)。

这能在自然闲聊中提示执行，不依赖“健康咨询”关键词。插件仍依靠当前模型遵循指令、调用工具；它不是另一个自动分析模型，也不是已安装到实际 profile 的后台服务。中断、工具限制、输入不足或模型未执行均可能留下观察空白，不能把空白解释为正常。

**手动技能/CLI 接入。** 宿主直接从当前可见的原始上下文准备 JSON，经标准输入调用根目录 `cognition.py chat-prepare`，完成模板后再经标准输入调用 `chat-record`；`chat-stats --days 30` 查看聚合。完整 CLI 参数以 `python3 cognition.py --help` 为准。不要在参数中嵌入原文、写临时原文文件或把整个 payload 打印到日志。

```sh
python3 /absolute/path/Family-Doctor-Agent/cognition.py --profile 实际profile chat-prepare
python3 /absolute/path/Family-Doctor-Agent/cognition.py --profile 实际profile chat-record
python3 /absolute/path/Family-Doctor-Agent/cognition.py --profile 实际profile chat-stats --days 30
```

前两条命令从 stdin 接收 JSON；在 Hermes 工具中以进程输入传递数据，不需要用户手工填写诊断量表。共享家庭目录通过 `FAMILY_DOCTOR_FAMILY_HOME` 或全局 `--home` 指定。不是 `family.py run` 子工具，也不是 Web 中的 JSON/CSV 观察导入格式。

## 分析步骤

1. 先处理当前任务与急性危险信号，再确认实际说话者、被观察成员、本人/家属来源和输入方式。
2. 获取有限原始窗口。本人表达与家属代述分开；转发、混合账号、AI 摘要、历史时间不明等标记限制或排除，不能伪装成本人当前语言样本。
3. 调用 prepare 获取全部维度模板。默认 `not_assessable`，没有真实回应机会时保留该状态。
4. 按[详细九维规则](../skills/family-doctor/references/chat-cognition-rubric.md)检查重复提问、上下文记忆、理解回应、话题连贯、时间顺序、找词表达、定向、计划组织和日常功能。逐机会比对先前上下文，排除合理反例，引用用户原句。
5. record 将原始输入与结构结果一起送入本地内存校验。插件工具使用 `preparation_id`、`analysis`；发现新的限制可用 `additional_conditions` 追加，不能清除已有条件。失败时修正字段或保留不足，不能换编号绕过冲突；成功只返回回执，不在飞书复述结果。
6. Web 读取去原文统计和复核提示。家庭成员在本机查看，不额外发消息、不自动建立随访任务。

## 输入与证据约定

顶层输入为 `schema_version: 1`、`session_id`、`window_id`、`member`、`source_mode`、`input_mode`、`conditions`、`messages`。record 另外包含 `analysis`。每条消息为 `id`、`role`（`user`/`assistant`）、`at`（带时区 ISO 8601）和 `text`。`source_mode` 为 `self` 或 `caregiver`，`input_mode` 为 `text` 或 `voice`。

本人模式只能指向当前登记 profile 对应成员；家属模式指向另一位已登记成员。profile 不是人员身份认证，共用账号或代录不能据此假装是本人。

`analysis.dimensions` 必须包含九个固定维度。每维包含 `status`（`not_assessable`、`no_signal`、`possible_signal`）与 `opportunities`。每个机会包含 `response_ids`、`context_ids`、`outcome` 和 `evidence: [{message_id, quote}]`。引用必须出自所关联的用户回应且精确匹配；助手文字只作先前上下文。前四维必须引用先前上下文。`analysis.urgent` 单独保存急性变化状态、原因枚举与变化/起病证据；不借普通累计门槛压掉急性信息。

质量条件分为：

| 类别 | 固定值 | 处理 |
|---|---|---|
| 排除 | `shared_account`、`quoted_or_forwarded`、`source_uncertain`、`not_current` | 不进入有效本人观察；先澄清来源。 |
| 受限 | `asr_uncertain`、`missing_context`、`assistant_misunderstanding`、`ambiguous_prompt`、`fatigue`、`mood`、`medication`、`hearing_vision`、`mixed_quotation` | 保留质量限制，不把受影响的判断当作可靠长期变化。 |

两条用户消息、三条总消息只是最低上下文要求，并非足够诊断；低于门槛自动标为受限。相应维度没有机会仍为不可判断。

## 时间、去重与有限上下文

插件使用它首次收到本轮消息的真实本机时间，标记为 `local_observed_at`。这是**接收观察时间**，不是飞书发送时间，更不是用户所描述症状的发生时间。只采集启用后的新消息，不反向猜测历史记录。接收延迟可能影响按日统计；插件重启后的窗口需要重新自然积累。

手动接入有真实消息时间则据实使用。缺少历史平台 ID 时，可用会话、角色、真实时间和原文 SHA256 生成带 `local_` 前缀的稳定标识，并明确这是本地标识；不能使用随机编号、每轮序号或现在时间补造历史。插件准备票据属于当前会话，不可拿到其他 profile 提交。

同一窗口重试保持编号与内容不变；修改同一键内容会冲突。重叠窗口每维只计新增回应，避免一段话在每轮被反复统计。核心还用提供者、角色、真实观察时刻及文本摘要识别只换 ID 的重复输入；真实发生在不同时间的再次表达不因内容相似而删除。本人和家属结果分开，不把两者相加成老人本人异常次数。

插件按实际成员编号、本人/家属和输入方式分段。切换对象或从文本切换语音时，从本轮新用户消息重新积累，不复用上一段上下文；同一消息已经归属后不能改人或改方式。已知质量限制按消息保留，后续窗口包含该消息时继续带入，不能用空条件清除。核心自动判断的 `missing_context` 可随窗口自然完整而改善。

插件上限为 128 个活跃会话、每会话 24 条消息/240 KiB、每条 12000 字符，一小时闲置后窗口失效并在后续访问时清理；容量不足淘汰最久未使用窗口。原文只在插件进程内存中，重启即丢弃。超长、非文本或缺少真实路由标识的输入不强行纳入。工具与宿主本身的会话历史可能记录输入输出，详见[隐私边界](../PRIVACY.md)。

## 聚合和 Web 提示

统计窗口以实际记录的观察日期计算，本人表达按输入方式分开比较。近 30 天内，同一维度、同一来源类别（本人或家属分别统计）在至少三个独立日期出现有效可能线索时，Web 显示需要进一步核实的提示；单次可能线索只保留为观察。该门槛是工程规则，不是患病概率、临床风险分层或诊断结论。

家属跨日复述同一次旧事件须标记 `not_current` 或保留资料不足，不能用每次接收时间制造新的异常日期。插件无法自行判断语义上的历史事件重述，当前模型必须核对是否真实新发生。

历史参考只来自当前统计窗口之前 90 天的本人同输入方式可用观察；同维度至少有六个历史独立可评估日期、当前窗口至少三个独立可评估日期时，才形成早期参考。当前维度混合文本与语音时不进行该比较。比较仅表示线索比例增加或未增加，不代表健康基线、恢复正常或疾病概率。缺少历史参照、对话机会不足或质量受限时，明确显示资料不足；统计缺口也不能解释为改善。

明确有突然变化及起病证据时，Web 单独展示及时核实/就医提示，不等待三个日期。其内容也不自动推送飞书。正常医疗安全回应按当前情况继续执行。

Web 当前展示本人/家属片段数、独立天数、九维机会和线索天数、早期参考及复核提示。聊天趋势 API 提供按日聚合，但页面尚未绘制聊天折线；当前折线属于手工补充观察。手工 JSON/CSV 观察仍由 `cognition.py validate/import` 管理，保存于 `cognition/observations.json`；聊天观察保存于独立的 `cognition/chat-observations.json`，两类不能重复相加成一个患病分数。

## 实际边界

本地校验能确认引用真的存在、上下文顺序与身份归属正确、数据不重复；无法证明 LLM 的含义理解正确。没有训练或验证独立痴呆预测模型，没有临床量表自动评分，也没有自动确诊。

仅 Web 提示是一项输出约定。项目没有消息发送代码，但无法仅靠指令保证宿主的流式输出、工具进度、推理显示或日志绝不暴露分析；应在实际 Hermes 配置中核验这些显示方式，不能用最终回复过滤器声称抹掉已流出的内容。模型继续使用现有 Hermes 服务，其原有数据处理范围没有因此消失。
