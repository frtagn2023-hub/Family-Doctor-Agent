# 认知观察统计：数据口径与医学边界

## 当前实现

**后台只做认知观察统计、Web 复核提示和结构化导入，不展示一般健康档案或聊天原文。** 数据有两条独立路径：手工 JSON/CSV 观察包含归属、来源、时间、质量、信号与影响因素；聊天观察由 Hermes 当前模型逐维核对原始多轮上下文，再经本地内存校验后保存去原文结果。两类数据不合成为患病分数。手工导入见[统计与导入说明](web-dashboard.md)，聊天处理见[分析流程](chat-analysis.md)。

手工路径支持来源校验、预览、去重、事件关联和整批保存；聊天路径支持九维机会/证据校验、重叠窗口去重、质量限制、历史参考与 Web 规则提示。可选 Hermes 插件让当前模型在自然交流中执行该流程，需要另行启用；没有独立后台模型、临床认知测试、患病概率评分或飞书认知风险推送。校验成功不能证明模型的语义解释或临床判断正确。

合成演示只展示页面和统计形式，不属于实际成员观察；演示模式不能提交到真实家庭。没有有效观察时保持“尚未评估”，不能从零记录推导认知正常或低风险。

## 手工导入：来源与归属

每条观察分别记录被观察成员和提供者 profile。两者必须能定位到家庭登记；姓名重复时使用稳定成员编号，不按昵称、文件名或“我爸”等称呼猜测成员。

| 来源类型 | 导入要求 | 统计含义 |
|---|---|---|
| 本人表达 `self_expression` | 提供者 profile 对应被观察成员 | 只有可用的这一类来源能增加本人语言样本数。 |
| 家属观察 `caregiver_observation` | 提供者与被观察成员不同 | 单独记录家属观察，不能代替老人的本人表达。 |
| 医生记录来源 `clinician_record` | 提供者为已登记的上传者 | 保存来源类别，不表示验证上传者具有医生身份，也不是语言样本。 |

profile 关联是数据归属约定，不是实际发言者的身份认证。共用账号、混合群聊、转发或 AI 摘要不能仅凭 profile 被标为老人本人表达。实际来源不明时先核实，不为通过校验而改写角色。

## 手工导入：质量、去重与事件关联

`usable` 表示该来源可纳入观察统计；`limited` 和 `excluded` 保留为资料质量信息，不进入有效观察趋势。这是输入者对质量的声明，工具不会自动判断某段语言是否可靠。转写、听视力、睡眠、情绪、药物等可能因素按固定类别保留；后台不会自行宣布已经排除这些因素。

同一成员、同一提供者 profile、同一 `source_record_id` 构成稳定去重键。相同内容重试跳过；内容不同则整批拒绝，不能静默覆盖。批内重复和历史重复遵循相同规则。

本人和家属对同一次观察的补充可以使用相同 `event_key`，但必须属于同一成员且实际 `observed_at` 完全一致；不同 UTC offset 表达同一时刻仍可匹配。同键不同实际时刻会停止整批导入，防止将跨时段真实重复行为错误合并。未提供事件键时，不按词语相似度或上传时间自动合并。

因此，“重复提交”和“反复提问”是两件事：前者不能重复计数，后者若真实发生在不同时间，应保留为不同观察。既有一般问诊的合并规则不会自动套用到认知观察中。

## 手工导入：近 30 天统计

统计窗口使用上海日历，包含当前日期及之前 29 个日期；导入时间和实际观察时间分别保存，窗口按实际观察时间计算。无时区、未知或未来的发生时间不能以上传时刻替代。旧观察可以导入留存，但不计入当前窗口。

| 指标 | 计算口径 |
|---|---|
| 有效来源数 | 窗口内 `quality=usable` 的来源记录数量。 |
| 独立观察事件数 | 将有效来源按已明确的事件键关联；未提供事件键的来源各自独立。 |
| 待核实事件数 | 有效独立事件中，至少一份来源含一个信号的事件数；多个信号或多位提供者不重复增加事件数。 |
| 本人语言样本数 | 至少有一份可用本人表达来源的独立事件数；家属或医生来源不增加该指标。 |
| 来源与质量分布 | 区分本人、家属、医生记录，以及可用、受限和排除记录，说明资料覆盖情况。 |
| 变化趋势 | 按实际日期聚合有效独立事件和有信号事件；数量不是疾病概率、严重程度或经过验证的认知分数。 |

导入多个来源不等于增加多次独立异常，窗口内没有记录也不等于进行了足够观察。提供者数量不能替代样本质量或临床复核。

当前状态只反映资料情况：

| 状态 | 含义 |
|---|---|
| 尚未评估 `not_assessed` | 当前窗口没有有效观察，无法据此判断认知状况。 |
| 已记录观察 `recorded` | 当前窗口有有效观察，但未录入信号；不等于正常或低风险。 |
| 待核实变化 `needs_review` | 当前窗口有有效信号，值得进一步核实来源与背景；不等于确诊或高患病风险。 |

这些状态没有自动就医分级含义。后台不从记录数、附加资料数量或模型置信度计算痴呆概率。

## 医学定位

本项目用于整理值得了解的认知变化，不能独立诊断痴呆或阿尔茨海默病。NHS 指出，痴呆诊断结合病史、日常生活影响、认知测评及其他检查，没有单一诊断测试；正式认知测试本身也不能独立确诊。将聊天或观察作为线索，是据此作出的产品设计选择。[NHS：痴呆的诊断检查](https://www.nhs.uk/conditions/dementia/symptoms-and-diagnosis/tests/)

NICE 建议同时了解本人及熟悉其情况者的认知、行为、心理变化和日常生活影响，并调查谵妄、抑郁、感官障碍、药物影响等可能原因。录入一个信号不代表已排除这些解释。[NICE NG97：评估、管理与支持建议](https://www.nice.org.uk/guidance/ng97/chapter/Recommendations)

NIA 指出，个人基线有助于未来比较，认知变化需要进一步的认知、行为或功能评估；部分问题可能与药物、抑郁等因素有关。当前计数趋势尚未建立个人临床基线，也不能代替这类评估。[NIA：老年患者认知障碍的评估](https://www.nia.nih.gov/health/health-care-professionals-information/assessing-cognitive-impairment-older-patients)

突然明显意识混乱应及时寻求医疗帮助，不应等待导入、长期趋势或累计信号。即使已经确诊痴呆，突发变化也不能自动解释为一般病程进展。[NHS：突然意识混乱](https://www.nhs.uk/symptoms/confusion/)

已经确诊的成员应以照护变化和随访为重点，保留医生诊断来源；当前导入格式不接受 AI 生成的诊断状态，也不会根据聊天自动设为已确诊。照护沟通与计划需要结合本人和家属情况。[NIA：认知障碍患者的照护](https://www.nia.nih.gov/health/health-care-professionals-information/caring-older-patients-cognitive-impairment)

## 聊天分析与 Web 提示

Hermes 当前模型按[九维规则](../skills/family-doctor/references/chat-cognition-rubric.md)检查重复提问、上下文记忆、理解回应、话题连贯、时间顺序、找词表达、定向、计划组织和日常功能。每维都显式填写，不存在机会时为不可判断；存在机会时核对前文与用户原句。前四维必须引用先前上下文，助手自己的表达不能当成成员认知证据。

本人表达和家属报告分别统计。转写、共用账号、引用、疲劳、情绪、听视力、药物、问题歧义或助手误解等必须保留限制；`limited/excluded` 不增加有效维度机会。只换消息标识、重试同一窗口或反复包含旧消息不能重复增加计数；不同时间真实再次出现的情况保留。插件切换目标或输入方式时从新消息重新积累窗口，避免把家属本人表现写到老人名下。

近 30 天同维度在至少三个独立日期有有效可能线索时，Web 提示家属复核；少于该门槛的单次线索只作为观察。历史参考要求当前窗口之前 90 天同输入方式的本人可用观察在该维度达到六个独立日期，且当前窗口至少三个独立日期；当前混合输入方式时不比较。参考不是正常基线，比例未增加也不等于排除疾病。规则仍需实际误报/漏报评估，软件测试不能证明医疗有效性。

急性变化需要变化与急性起病两类精确原句证据，独立于多日累计门槛。受限窗口仍可保留明确急性信息，来源已排除的窗口不产生此类提示。Web 状态为“观察资料不足”“持续观察”“建议家属复核”或“突发变化需及时关注”，不使用低/中/高患病概率。

认知提示只在 Web，不自动发送飞书通知，不在普通回复或过程说明里主动披露分析报告。直接询问功能时如实解释；真实急症的当轮安全与就医协助继续有效，不能被静默统计设置压掉。没有秘密认知测试、诱导错误、诊断宣告或主动联系医生的流程。

## 隐私边界

手工观察和聊天观察分别保存于家庭目录的 `cognition/observations.json`、`cognition/chat-observations.json`。聊天原文与引用只作内存校验，落盘仅来源/时间元数据、枚举、计数与哈希；统计接口返回姓名与聚合信息，不返回逐条观察、原始 profile、来源键、事件关联键、聊天、模型提示词、检查结果或文件路径。导入拒绝未约定字段，不把原文件或自由摘要留作附件。

可选插件只在进程内有限缓存启用后的新消息，不扫描历史库，重启丢弃原文窗口；接收观察时间不能冒充平台发送或症状发生时间。启用后仍依赖当前模型执行工具，不能保证每轮都分析，也不能保证宿主工具历史、流式输出或日志已隔离。

不新增家庭授权审批；成员和来源的校验用于防止串档。本机统计也不能改变 Hermes 模型服务原有的数据处理范围，详见 [PRIVACY.md](../PRIVACY.md)。开源仓库只包含代码、空模板和合成示例，不包含真实观察与家庭登记。
